# Пачка 03 — Linux: поиск, hit-test, слежение за фокусом

Зависит от: 02 | Стенд: Ubuntu VM, X11 и Wayland сеансы

## Цель
То, что делает inspect.exe кроме дерева: показать элемент под курсором и в
фокусе, следить за изменениями, подсказать устойчивый селектор.

## Прочитать
- [contracts.md](contracts.md) §3, §5, §8.
- [platform-notes.md](platform-notes.md) — Linux, «Координаты».
- `crates/hangui-linux/src/` — только модуль провайдера.

## Задачи
1. `find <selector>` на реальном дереве (матчер из 01 поверх провайдера 02).
2. `inspect --at X,Y`: `Component.GetAccessibleAtPoint` от окна верхнего
   уровня, содержащего точку, рекурсивно вниз. `inspect --focused`.
3. Метод событий в `Provider` (обновить contracts §8): фокус, изменение
   имени/состояния, появление/исчезновение детей. `hangui watch --focus`
   печатает каждую смену фокуса строкой узла + селектором.
4. Генерация селектора для узла: самый короткий уникальный из `id` →
   `name` → путь с `:nth`; выводится в `inspect` и `watch`. Тест: для каждого
   узла фикстуры сгенерированный селектор находит ровно его.
5. `watch --hover` (X11): опрашивать позицию указателя (`x11rb`
   `QueryPointer`) 5 раз/с и печатать узел под ним при смене.
6. Wayland: измерить, что отдают `GetAccessibleAtPoint` и `extents`; если
   координат нет — `inspect --at` и `watch --hover` возвращают `unsupported`
   с советом использовать `--focused`. Исправить platform-notes.

## Не делать
- Подсветку элемента рамкой на экране (оверлей) — вне плана.
- Свой поток событий поверх опроса дерева — только события AT-SPI.

## Готово, когда
- На X11: навёл курсор на кнопку kesl-gui → `watch --hover` показал её;
  `inspect --at` по центру `bounds` любой кнопки возвращает её саму.
- `watch --focus` на Tab по окну kesl-gui печатает последовательность
  элементов (вывод в PROGRESS).
- На Wayland поведение измерено и задокументировано.

## Стоп-и-спроси
- События AT-SPI от kesl-gui не приходят (Qt шлёт не всё) — решить, нужен ли
  опрос как запасной путь.
