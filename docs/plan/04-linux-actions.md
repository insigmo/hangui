# Пачка 04 — Linux: семантические действия и ожидание

Зависит от: 03 | Стенд: Ubuntu VM (gnome-calculator, «Параметры»)

## Цель
Управлять элементами через API доступности, без мыши и клавиатуры.

## Прочитать
- [contracts.md](contracts.md) §4, §5, §6.
- `crates/hangui-linux/src/` — провайдер и таблица ролей.

## Задачи
1. `perform` для семантических действий §4:
   - `invoke` — `Action.DoAction` по имени (`click`/`press`/`activate`/
     `jump`, порядок поиска зафиксировать в коде с комментарием, откуда он);
   - `focus` — `Component.GrabFocus` (на GTK4 возвращает ошибку — проверено
     в 00; тогда `unsupported`, не молчаливое «ok»);
   - `set_value` — `EditableText.SetTextContents`, для чисел
     `Value.SetCurrentValue`;
   - `toggle` / `expand` / `collapse` — через действия узла, проверка
     результата по StateSet;
   - `select` — `Selection.SelectChild` у родителя;
   - `scroll_into_view` — `Component.ScrollTo`.
2. До действия: перечитать узел, нет `enabled` → `disabled` (exit 9).
   После: если состояние не изменилось там, где должно (`toggle`), —
   ошибка с описанием, а не `ok`.
3. `hangui do`, `--dry-run` (печатает найденный узел и выбранный метод).
4. `hangui wait <selector> [--gone] [--state S] [--timeout]` — по событиям
   из 03, с опросом раз в 250 мс как страховкой.
5. Сценарий-приёмка `scripts/e2e-a11y.sh`: калькулятор — нажать `7`, `+`,
   `5`, `=` через `invoke`, дождаться `12` в `source_view`; `set_value`
   `2*21` → `=` → `42`; «Параметры» — перейти в раздел и дождаться его
   заголовка.

## Не делать
- Запасной путь через ввод — пачка 06 (здесь `via` всегда `semantic`,
  иначе `unsupported`).
- kesl-gui — его действия идут через зонд (пачка 05).

## Готово, когда
- `scripts/e2e-a11y.sh` проходит на VM 3 раза подряд (вывод в PROGRESS).
- Для каждого действия §4 есть хотя бы одна проверка на реальном элементе,
  список в PROGRESS.

## Стоп-и-спроси
- Действие из §4 не реализуется через AT-SPI ни в одном GTK-приложении.
