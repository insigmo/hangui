# Пачка 06 — MCP-сервер для ИИ

Зависит от: 04 (05 желательно) | Стенд: Ubuntu VM + Claude Code как клиент

## Цель
Главная цель продукта: ИИ-агент видит карту приложения и управляет им через
MCP-инструменты.

## Прочитать
- [README.md](README.md) — D7, D11.
- [contracts.md](contracts.md) §1, §4, §6, §7.
- `crates/hangui-core/src/` — трейт `Provider`, рендер.

## Задачи
1. Крейт `crates/hangui-mcp` (`rmcp` 3.8, stdio, tokio); подкоманда
   `hangui mcp`. Вызовы провайдера — через `spawn_blocking` (D6).
2. Инструменты §7. `snapshot` — текстовое дерево §5 с префиксом `[eN]` у
   каждой строки; таблица ссылок на сессию; новая `snapshot` обнуляет таблицу.
3. Ссылка на исчезнувший элемент → `stale`; ошибки — текстом с `fix`, чтобы
   модель могла исправиться сама.
4. Ограничение размера: `snapshot` без `depth` у большого дерева обрезается
   на N узлов с пометкой, как получить остальное (`selector`/`depth`).
   N подобрать по kesl-gui, записать.
5. Описания инструментов — короткие, с примером селектора; проверить, что
   модель без подсказок пользователя делает сценарий из п. «Готово».
6. Тесты на `FixtureProvider`: каждый инструмент, ссылки, `stale`.

## Не делать
- HTTP/SSE-транспорт, авторизация, многопользовательность.
- Скриншоты в ответах инструментов.

## Готово, когда
- Claude Code с `hangui mcp` (запуск на VM, конфиг в `docs/mcp.md`) по
  просьбе «открой в kesl-gui раздел X и скажи, что в статусе» выполняет её
  только инструментами hangui. Лог вызовов — в PROGRESS.
- Тесты на фикстуре зелёные.

## Стоп-и-спроси
- Модель регулярно путает ссылки и селекторы — обсудить формат до правок
  контракта.
