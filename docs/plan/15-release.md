# Пачка 15 — Сборка, CI, релиз, документация

Зависит от: 08, 12, 14 | Стенд: GitHub Actions

## Цель
Любой человек скачивает один маленький файл, запускает `hangui doctor` и
начинает — ничего не доустанавливая (D18). SDK скачивают тот же файл сами
(D19).

## Прочитать
- [README.md](README.md) — D18, D19; [contracts.md](contracts.md) §5, §7, §11.6.
- [architecture.md](architecture.md) — «Поставка».
- `docs/linux-matrix.md` (из 10).

## Задачи
1. CI: fmt, clippy, test на ubuntu/windows/macos; Linux-сборка без
   графического сеанса (тесты на фикстурах).
2. Релиз по тегу: бинарники linux x86_64/arm64 (`cargo zigbuild`, glibc
   2.17), windows x86_64/arm64 (`+crt-static`), macos arm64/x86_64 — по
   architecture.md «Поставка», с CI-матрицей зондов внутри. Артефакты:
   архивы для людей, одиночные `hangui-<версия>-<os>-<arch>.gz` для SDK,
   `SHA256SUMS`, и `dist/checksums.json` (sha256 распакованных бинарей) —
   его вшивают в пакеты SDK при их сборке (§11.6).
3. Проверка «без зависимостей» в CI на каждый бинарь: `ldd` — только glibc,
   `dumpbin /dependents` — только DLL Windows, `otool -L` — только
   системные; запуск `hangui version` и `hangui --fixture … tree` в чистых
   контейнерах/раннерах без Rust и без пакетов (Ubuntu 18.04, Debian,
   Fedora; Windows Server Core; macOS).
4. Бюджет размера: CI печатает размер каждого бинаря и падает, если он
   > 10 МБ или вырос > 5% от прошлого релиза без строки в PROGRESS
   (таблица размеров по ОС — в PROGRESS и в release notes).
5. Пользовательская документация: README (установка = скачать один файл,
   `doctor`, 5 примеров CLI), `docs/mcp.md` (подключение к Claude Code и
   другим MCP-клиентам), `docs/selectors.md`.
6. Windows: опциональная сборка с `uiAccess` и инструкция по подписи;
   macOS: подпись и нотаризация, если владелец даст сертификаты.

## Не делать
- Пакеты для дистрибутивов (deb/rpm/brew) — после первого релиза.
- Отдельные «лёгкие» сборки, UPX и другие упаковщики (README «Не делать»).

## Готово, когда
- Тег `v0.1.0` даёт релиз со всеми бинарниками; скачанный бинарь на чистой
  Ubuntu VM проходит `doctor` и `tree` для kesl-gui, ничего не
  доустанавливая (зонд Qt — изнутри бинаря).
- Проверка зависимостей (п. 3) и бюджет размера (п. 4) зелёные на всех
  целях; таблица размеров — в PROGRESS.

## Стоп-и-спроси
- Сертификаты подписи, публикация релиза — только с явного согласия владельца.
