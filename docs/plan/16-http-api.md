# Пачка 16 — Локальный HTTP API (`hangui serve`)

Зависит от: 08 (общий слой операций с MCP), 04, 05 | Стенд: любая ОС на фикстуре; Ubuntu VM для приёмки

## Цель
Бинарь поднимает локальный HTTP API, через который тесты на любом языке
работают с hangui без разбора консольного вывода. Это фундамент пачек
17–20: SDK — тонкие клиенты этого API. CLI остаётся как есть (D14): разовые
«получить» и «нажать» — через параметры командной строки, тесты — через API.

## Задачи
1. Вынести операции, общие для MCP и HTTP (apps, launch, tree, find,
   inspect, act, wait, screenshot, doctor), в один слой в `hangui-core`
   (или `crates/hangui-service`, если в ядре появится tokio — D6 запрещает).
   MCP-инструменты переходят на него без изменения поведения.
2. Крейт `crates/hangui-http` (`axum` 0.8, tokio); подкоманда
   `hangui serve` по §10.1. Вызовы провайдера — через `spawn_blocking`,
   запросы к провайдеру сериализуются одним мьютексом (GUI однопоточен).
3. Эндпоинты §10.3 — тела запросов и ответов те же, что у CLI
   `--format json` (§1, §4, §6), чтобы команду из CLI можно было один-в-один
   перенести в тест.
4. Автоожидание (§10.4): `act`, `inspect`, `screenshot` ждут ровно одно
   совпадение (для `act` — ещё `visible` и `enabled`) до `timeout_ms`;
   ошибка `timeout` несёт последнюю причину (`not_found` / `ambiguous` с
   кандидатами / `disabled`).
5. Учёт запущенных приложений: `launch` запоминает pid; `close` закрывает
   (мягко, затем `kill` по таймауту); при остановке сервера закрываются все
   запущенные им приложения, если не `--keep-apps`.
6. Безопасность (§10.2): слушать только `127.0.0.1`; проверка `Host`;
   отказ на запрос с заголовком `Origin` (браузер не должен кликать по
   рабочему столу); токен из файла состояния. `--host` не-loopback — только
   вместе с явным `--token`.
7. Файл состояния и строка готовности (§10.1) — их читают SDK.
8. `POST /v1/selector` (§10.3): по точке, фокусу или ссылке строит самый
   устойчивый селектор (приоритет: `id` → `name`+роль → путь с `:nth`). Тот
   же инструмент `selector_for` — в MCP (§7): ИИ исследует приложение через
   MCP и переносит селекторы в тест.
9. `--fixture`: сервер на `FixtureProvider`, плюс `POST /v1/fixture/reset`.
   На этом SDK тестируются в CI без графического сеанса.
10. Кросс-языковой набор `sdk/conformance/cases.json`: запрос → ожидаемый
    ответ/ошибка на `tests/fixtures/sample-app.json` (каждый эндпоинт,
    каждый код ошибки, автоожидание, `reset`). Rust-тест гоняет его против
    сервера; пачки 17–20 гоняют его из своих SDK.
11. contracts.md §6 (`port_in_use`, `forbidden`), §7 (`selector_for`),
    §10, §11 записаны при планировании — сверить с реализацией, расхождения
    исправить в контракте и отметить в PROGRESS до пачек 17–20.

## Не делать
- WebSocket/SSE, поток событий (`watch` по HTTP) — по запросу владельца.
- Сессии и ссылки `eN` в HTTP: тест адресует только селекторами (D7, D15).
- Несколько клиентов с разными правами, TLS, пользователи.

## Готово, когда
- `hangui serve` печатает строку готовности, `curl :7357/v1/health` отвечает;
  второй `hangui serve` на тот же порт — exit 10 `port_in_use`;
  `--port 0` выбирает свободный порт и печатает его.
- Rust-тест проходит `sdk/conformance/cases.json` целиком на фикстуре.
- На стенде: `curl` по §10 запускает kesl-gui с зондом, нажимает «View»,
  дожидается узла, закрывает приложение (команды и ответы — в PROGRESS).
- Запрос с `Origin: http://example.com` и запрос без токена → 403.
