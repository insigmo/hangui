# Пачка 21 — Руководство для ИИ, примеры, публикация SDK

Зависит от: 15, 17, 18, 19, 20 | Стенд: Ubuntu VM + Claude Code; CI

## Цель
ИИ-агент без подсказок пишет на любом из четырёх языков тест, который
проходит повторно без ИИ; пакеты ставятся из PyPI, Go proxy, npm, NuGet.

Работа в двух местах (D20): руководство, `llms.txt` и релизные артефакты —
в репозитории hangui; README, примеры и публикация пакетов — в репозиториях
`hangui-python`, `hangui-go`, `hangui-js`, `hangui-dotnet`.

## Задачи
1. `docs/testing.md` — руководство «как ИИ пишет тест на hangui»:
   исследовать приложение через MCP (`snapshot`, `selector_for`) →
   переносить **селекторы**, не ссылки `eN` → действие с автоожиданием →
   проверка через `wait`/`inspect`; что делает тест устойчивым (`id` вместо
   `:nth`, без `sleep`, без координат, `vision` только с проверкой
   `confidence`); одна и та же проверка на четырёх языках.
2. `llms.txt` в корне hangui (со ссылками на четыре репозитория SDK) и
   короткий раздел в README каждого репозитория SDK (установка, запуск
   сервера, пять строк теста, таблица ошибок, ссылка на `docs/testing.md`) —
   чтобы ИИ, которому дали только пакет, нашёл, как им пользоваться.
3. Примеры `examples/` в каждом репозитории SDK на двух целях:
   gnome-calculator (a11y) и kesl-gui (зонд), один и тот же сценарий на
   всех языках; `docs/testing.md` ссылается на них.
4. Версии: SDK и бинарь выпускаются одной версией; SDK проверяет
   `protocol` (§10.3 `health`) и говорит, какую версию hangui поставить.
5. Публикация — из CI каждого репозитория SDK по его тегу `vX.Y.Z`, после
   релиза hangui той же версии: PyPI (trusted publishing), npm
   (provenance), NuGet, Go proxy (тег `hangui-go`); каждый шаг — только с
   согласия владельца. В hangui — порядок выпуска в `docs/releasing.md`:
   тег hangui → релиз с бинарями, `checksums.json`, набором совместимости →
   подъём `HANGUI_VERSION` в репозиториях SDK → их теги.
6. Сборка пакетов SDK вшивает таблицу sha256 из `checksums.json` релиза
   hangui той же версии (§11.6); CI SDK проверяет, что версия пакета =
   версия бинарей, а адреса `.gz` из таблицы отвечают 200. Бинаря внутри пакетов
   нет — его скачивает сам SDK (D19); `docs/testing.md` и README SDK
   описывают `HANGUI_BIN`, `HANGUI_DOWNLOAD=0`, `HANGUI_DOWNLOAD_URL` и
   предзагрузку для CI без сети.

## Не делать
- Генератор тестов, запись действий в тест (README «Не делать»): тест
  пишет ИИ, hangui даёт ему MCP для исследования и SDK для кода.

## Готово, когда
- Claude Code с MCP hangui и только `docs/testing.md` в контексте пишет
  на каждом из четырёх языков тест «нажать View в kesl-gui и проверить
  заголовок страницы»; каждый тест затем проходит 3 запуска подряд без ИИ
  (лог в PROGRESS).
- Пакеты установлены из реестров на чистой VM, примеры проходят.

## Стоп-и-спроси
- Любая публикация в реестр, резервирование имён и префиксов, создание
  репозиториев SDK и секретов публикации в них.
