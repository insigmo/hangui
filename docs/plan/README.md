# hangui — план разработки

Цель: один кроссплатформенный инструмент на Rust, который для **любого**
GUI-приложения строит **топологическую карту** (дерево окон и элементов с
текстами, ролями, состояниями, координатами — как `inspect.exe` на Windows)
и умеет **управлять этими элементами**. Главный потребитель — ИИ-агент,
второй — человек. Платформы: Linux (почти все графические оболочки), затем
Windows, затем macOS. Пока консольное приложение.

Как достигается «любое приложение» — [architecture.md](architecture.md):
лестница источников карты (API доступности → зонд внутри процесса / CDP →
пиксели + OCR) и лестница действий (семантика → событие внутри процесса →
ввод ОС).

Порядок работы задан владельцем: сначала Linux на стенде Ubuntu (VMware) с
`kesl-gui`, потом Windows, потом macOS.

## Как пользоваться планом

- Пачки выполняются по номеру: «сделай пачку 03». Одна пачка — одна сессия.
- Перед первой правкой: отметить пачку 🟡 в [PROGRESS.md](PROGRESS.md) и
  закоммитить; сверить `git status` с отметками (прерванная сессия оставляет
  код, но не статус).
- Читать только файлы из раздела «Прочитать» своей пачки +
  [contracts.md](contracts.md). [platform-notes.md](platform-notes.md) —
  только раздел своей ОС.
- По завершении: ≤10 строк в PROGRESS.md (что сделано, что проверено на
  стенде, что не получилось). Следующая сессия читает PROGRESS вместо кода.

## Решения (меняются только владельцем)

| # | Решение | Почему |
|---|---|---|
| D1 | **Лестница источников** (architecture.md): `a11y` → `probe`/`cdp` → `vision`. Каждый узел несёт `source`, каждое действие — `via`. Семантика предпочтительнее ввода по координатам, но ни одна ступень не обязательна: приложение без дерева всё равно получает карту. | Разведка 00: kesl-gui не отдаёт AT-SPI; зонд внутри процесса дал полную карту и управление (`docs/research/qt-probe-poc.md`). |
| D2 | **Rust workspace**, edition 2024, toolchain stable (сейчас 1.98). Модули — architecture.md «Модули». Зонды в тулкиты — на языке тулкита (C++ для Qt), минимальные; вся логика — в Rust. | Ядро и CLI тестируются на любой ОС; платформенный код изолирован `cfg(target_os)`, как в lumepeer. Зонд обязан говорить ABI тулкита. |
| D3 | **Linux:** `atspi` 0.30 + `zbus`; ввод X11 — `x11rb` 0.14 (XTest), Wayland — `ashpd` 0.13 (RemoteDesktop + ScreenCast в одной сессии). | Проверено в lumepeer; AT-SPI не зависит от оболочки. |
| D4 | **Windows:** крейт `windows` 0.62 напрямую (UIA, SendInput, Graphics.Capture). | Та же версия, что в lumepeer. |
| D5 | **macOS:** `objc2-application-services` 0.3 для AX; недостающее — тонкий `extern "C"`. Ввод — CGEvent, захват — ScreenCaptureKit. | Стек objc2 из lumepeer. |
| D6 | **`Provider` — синхронный трейт.** Асинхронные бэкенды (zbus, CDP) держат свой поток с tokio и делают `block_on`; MCP зовёт провайдер через `spawn_blocking`. | UIA и AX синхронны и привязаны к потокам. |
| D7 | **Адресация:** селекторы (contracts.md §3) — для CLI и скриптов; ссылки `e12` — только внутри сессии MCP/TUI до следующего снимка. Устаревшая ссылка → `stale`. | Компактный снимок для ИИ, устойчивые селекторы для людей. |
| D8 | **Роли нормализуются** (contracts.md §2), исходная — в `native_role`, исходный класс тулкита — в `class`. | Один селектор на всех ОС и источниках. |
| D9 | **Ошибки различают «нельзя», «запрещено», «выключено»:** `unsupported`, `permission_denied` (с `fix`), `disabled`. Действие над выключенным элементом — ошибка, не «ok». | lumepeer ADR 0110/0166; PoC: «Reports» был `enabled:false`, а клик ответил «ok». |
| D10 | **`hangui doctor [app]`** — проверяет окружение и для приложения говорит, какие ступени доступны и как включить следующую (`launch` с зондом, CDP-флаг, разрешение на захват). | «Инструмент для всех» ломается на окружении. |
| D11 | **Главный интерфейс для ИИ — MCP-сервер** (`rmcp` 3.8, stdio). `snapshot` отдаёт карту, а для `vision`-окон — и снимок (image content). | Мультимодальная модель сама дочитает то, что не взял OCR. |
| D12 | **Интерфейс для человека** — TUI-инспектор (`ratatui` 0.30). | Владелец: «пока консольное». |
| D13 | **Зонд — только в процессы того же пользователя, запущенные через hangui** (`hangui launch`), на Linux через `LD_PRELOAD`; `attach` к работающему — где ОС разрешает без повышения прав. Сборка зонда — под точную минорную версию тулкита цели, линковка с её библиотеками. | PoC: заголовки Qt 5.15 против Qt 5.9 давали пустые ответы. |
| D14 | **Два режима бинаря:** CLI — разовые «получить»/«нажать» через параметры; `hangui serve` — локальный HTTP API (contracts.md §10) для тестов и SDK. SDK говорят с hangui только по HTTP; консоль — лишь чтобы запустить `serve`. | Владелец (2026-10-29): ИИ пишет тесты, которые потом идут без ИИ; общение — нативное, через API, не разбор вывода. |
| D15 | **Порт по умолчанию 7357**, меняется `--port` (0 — свободный); SDK берут порт из аргумента, `HANGUI_URL`/`HANGUI_PORT` или по умолчанию. Тесты адресуют только селекторами, с автоожиданием. | Тест должен проходить повторно: ссылки `eN` живут до снимка (D7), `sleep` даёт нестабильность. |
| D16 | **SDK: Python, Go, TypeScript/JavaScript (один npm-пакет), C#** — тонкие клиенты §10 без зависимостей во время выполнения (кроме `System.Text.Json` на netstandard2.0); общий контракт — contracts.md §11, общий набор `sdk/conformance`. | Одно поведение на четырёх языках; SDK проверяются в CI на фикстуре без графики. |
| D17 | **Каждый SDK при старте проверяет, запущен ли hangui** (`GET /v1/health`): работает — подключается и не останавливает чужой сервер; нет — запускает свой `hangui serve` (в setup-фикстуре раннера) и останавливает его в конце. Бинарь для этого SDK находит или скачивает сам (D19). | Владелец: «hangui запускается в тестах, например в setup-фикстуре». |
| D18 | **Один бинарь на ОС/архитектуру, без зависимостей во время выполнения, минимального размера, и умеет всё.** CLI, MCP, TUI, `serve`, зонды, визуальный слой — в одном файле, без редакций «lite/full»; установка — скопировать файл. Linux — только glibc с базой 2.17 (статический musl не может подгрузить libpipewire; architecture.md «Поставка»), Windows — `+crt-static` (без VC++ Redistributable), macOS — только системные фреймворки. Системная библиотека, без которой функция в этой среде невозможна (libpipewire для ScreenCast), грузится `dlopen` при первом использовании: без неё бинарь работает, функция отвечает `unsupported` с `fix`. Тяжёлые данные (модели OCR) в бинарь не входят — скачиваются при первом использовании (architecture.md «Поставка»). **Бюджет — ≤ 10 МБ** на бинарь; CI не даёт вырасти > 5% без записи в PROGRESS. Сборке разрешено тянуть что угодно: тулчейны, кросс-компиляторы, заголовки и библиотеки Qt, SDK ОС. | Владелец (2026-10-29): «плевать, что при сборке нужно много чего качать, главное — бинарь маленький и умеет всё на всех ОС». Маленький самодостаточный файл SDK скачивают за секунды (D19). |
| D19 | **SDK сам находит или скачивает hangui** (contracts.md §11.6): аргумент → `HANGUI_BIN` → `PATH` → кэш → скачивание из релиза той же версии, что SDK, с проверкой sha256 по таблице, вшитой в пакет SDK. Срабатывает в любой точке входа, которой нужен свой сервер (`start()`, `launch(...)` без работающего сервера, фикстуры раннеров). О поиске и скачивании SDK **всегда пишет в консоль** (stderr): что не найдено, что, откуда и куда качает, размер, итог. `HANGUI_DOWNLOAD=0` запрещает скачивание. | Владелец (2026-10-29): «установили пакет на Python (или другом языке), вызвали `launch` — он проверяет, есть ли hangui; нет — скачивает и пишет об этом в консоли». Пакеты SDK остаются маленькими и без бинаря внутри. |

## Общие правила

- Каждое утверждение о поведении ОС в PROGRESS/доках помечается: *проверено
  на стенде* (команда + вывод) или *по документации* (ссылка).
- Перед «готово»: `cargo fmt --check`, `cargo clippy --workspace
  --all-targets -- -D warnings`, `cargo test --workspace`. Платформенный крейт
  проверяется на своей ОС (на Windows — `cargo check` для Linux-кода
  недостаточно: собирать на стенде или в WSL).
- Размер и зависимости (D18): новый крейт — с `default-features = false` и
  только нужными фичами; чистый Rust предпочтительнее обёртки над C;
  C-библиотеку, которой нет на любой машине этой ОС, — не линковать, а
  `dlopen` при первом использовании. Пачка, добавившая зависимость, пишет в
  PROGRESS размер release-бинаря до и после (`cargo bloat --release
  --crates` — если прирост > 200 КБ).
- Не трогать файлы других пачек; contracts.md меняет только пачка, которая
  вводит новый элемент, и пишет об этом в PROGRESS.
- Команды с root на стенде запускает владелец; агент пароль не вводит.

## Не делать (во всём плане)

- Запись и воспроизведение макросов, язык сценариев, плагины.
- GUI-приложение, веб-интерфейс, сетевой сервер кроме MCP по stdio и
  локального HTTP API `hangui serve` (D14).
- Обход защиты ОС и приложений: повышение прав, отключение UAC/TCC/UIPI/SIP,
  внедрение в процессы других пользователей или в системные службы.
- Обучение собственных моделей распознавания: только готовый OCR и снимок
  для ИИ.
- Java Access Bridge, Android, iOS.
- Урезанные редакции бинаря и функции, которые ставятся отдельным пакетом
  (D18); упаковщики исполняемых файлов (UPX и т.п.) — ложные срабатывания
  антивирусов и сломанная подпись macOS.
- Абстракции «на будущее»: трейт или крейт появляется, когда есть второй
  реальный пользователь.
