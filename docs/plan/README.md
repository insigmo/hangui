# hangui — план разработки

Цель: один кроссплатформенный инструмент на Rust, который строит
**топологическую карту GUI-приложения** (дерево окон и элементов с текстами,
ролями, состояниями, координатами — как `inspect.exe` на Windows) и умеет
**управлять этими элементами**. Главный потребитель — ИИ-агент, второй —
человек. Платформы: Linux (почти все графические оболочки), затем Windows,
затем macOS. Пока консольное приложение.

Порядок работы задан владельцем: сначала Linux на стенде Ubuntu (VMware) с
`kesl-gui`, потом Windows, потом macOS.

## Как пользоваться планом

- Пачки выполняются по номеру: «сделай пачку 03». Одна пачка — одна сессия.
- Перед первой правкой: отметить пачку 🟡 в [PROGRESS.md](PROGRESS.md) и
  закоммитить; сверить `git status` с отметками (прерванная сессия оставляет
  код, но не статус).
- Читать только файлы из раздела «Прочитать» своей пачки +
  [contracts.md](contracts.md). [platform-notes.md](platform-notes.md) —
  только раздел своей ОС.
- По завершении: ≤10 строк в PROGRESS.md (что сделано, что проверено на
  стенде, что не получилось). Следующая сессия читает PROGRESS вместо кода.

## Решения (меняются только владельцем)

| # | Решение | Почему |
|---|---|---|
| D1 | **Семантика первична.** Источник карты — API доступности ОС: AT-SPI2 (Linux), UI Automation (Windows), AXUIElement (macOS). Синтетический ввод (мышь/клавиатура по координатам) — только запасной путь, и результат действия всегда говорит, каким путём оно выполнено (`via: semantic \| input`). | Клик через API не зависит от разрешения экрана, DPI, перекрытия окон и Wayland-ограничений. |
| D2 | **Rust workspace**, edition 2024, toolchain stable (сейчас 1.98). Крейты: `hangui-core` (модель, селекторы, рендер, трейт `Provider`, без ОС-зависимостей), `hangui-linux`, `hangui-windows`, `hangui-macos`, `hangui-mcp`, бинарь `apps/hangui`. | Ядро и CLI тестируются на любой ОС; платформенный код изолирован `cfg(target_os)`, как в lumepeer. |
| D3 | **Linux:** `atspi` 0.30 + `zbus` (чистый Rust, без libatspi/C). Ввод: X11 — `x11rb` 0.14 (XTest); Wayland — `ashpd` 0.13 (портал RemoteDesktop). | Проверено в lumepeer (x11rb, ashpd); AT-SPI работает одинаково в GNOME/KDE/XFCE/Cinnamon/MATE/LXQt, т.к. это D-Bus, а не оболочка. |
| D4 | **Windows:** крейт `windows` 0.62 напрямую (COM `IUIAutomation`), без обёрток. Ввод — `SendInput`. | Та же версия, что в lumepeer; полный контроль над CacheRequest и потоками COM. |
| D5 | **macOS:** `objc2-application-services` 0.3 для AXUIElement; чего нет в биндингах — тонкий `extern "C"` (как `AXIsProcessTrusted` в lumepeer). Ввод — CGEvent. | Тот же стек objc2, что в lumepeer. |
| D6 | **`Provider` — синхронный трейт.** Linux-бэкенд держит свой поток с однопоточным tokio-рантаймом и делает `block_on`; MCP-сервер зовёт провайдер через `spawn_blocking`. | UIA и AX синхронны и привязаны к потокам; синхронное ядро проще для CLI. |
| D7 | **Адресация:** селекторы (contracts.md §3) — для CLI и скриптов; короткие ссылки `e12` — только внутри одной сессии MCP/TUI, действуют до следующего снимка. Устаревшая ссылка → ошибка `stale`, никогда не действие над другим элементом. | ИИ нужен компактный снимок со ссылками (как aria-snapshot в Playwright MCP), человеку и скриптам — устойчивые селекторы. |
| D8 | **Роли нормализуются** в один список (contracts.md §2), исходная роль ОС всегда сохраняется в `native_role`. | Один селектор работает на трёх ОС. |
| D9 | **«Нельзя» и «запрещено» — разные ошибки:** `unsupported` (оболочка не даёт API, например Cinnamon-Wayland без портала) vs `permission_denied` (ОС отказала, есть что исправить: TCC, UIPI, выключенная доступность). Каждая ошибка несёт подсказку, как исправить. | Урок lumepeer ADR 0110/0166: молчаливая деградация стоила сотен повторов. |
| D10 | **`hangui doctor`** — первая команда, которую видит пользователь: проверяет шину доступности, включённость тулкитов, тип сеанса, разрешения, портал. | «Инструмент для всех» ломается на окружении, а не на коде. |
| D11 | **Главный интерфейс для ИИ — MCP-сервер** (`hangui mcp`, stdio, крейт `rmcp` 3.8). CLI с `--format json` — второй путь. | MCP подключается к Claude Code и другим агентам без обёрток. |
| D12 | **Интерфейс для человека** — TUI-инспектор (`hangui tui`, `ratatui` 0.30): дерево, свойства, режим «под курсором/в фокусе». Отдельный GUI — вне этого плана. | Владелец: «пока консольное». |

## Общие правила

- Каждое утверждение о поведении ОС в PROGRESS/доках помечается: *проверено
  на стенде* (команда + вывод) или *по документации* (ссылка).
- Перед «готово»: `cargo fmt --check`, `cargo clippy --workspace
  --all-targets -- -D warnings`, `cargo test --workspace`. Платформенный крейт
  проверяется на своей ОС (на Windows — `cargo check` для Linux-кода
  недостаточно: собирать на стенде).
- Не трогать файлы других пачек; contracts.md меняет только пачка, которая
  вводит новый элемент, и пишет об этом в PROGRESS.

## Не делать (во всём плане)

- Распознавание экрана/OCR и «зрение» по скриншотам — не в этом плане (D1).
- Запись и воспроизведение макросов, язык сценариев, плагины.
- GUI-приложение, веб-интерфейс, сетевой сервер кроме MCP по stdio.
- Java Access Bridge, Android, iOS.
- Обход защиты приложений, повышение прав, отключение UAC/TCC/UIPI.
- Абстракции «на будущее»: трейт или крейт появляется, когда есть второй
  реальный пользователь.
