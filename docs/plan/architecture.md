# Архитектура: карта и управление для любого GUI

Цель — **любое** окно на экране превращается в карту (дерево элементов с
текстами, ролями, состояниями, координатами) и управляется. Ни один способ
не покрывает все приложения, поэтому hangui держит **лестницу источников** и
для каждого приложения берёт самый богатый доступный. Каждый узел карты
говорит, откуда он (`source`), и каждое действие — каким путём выполнено
(`via`).

## Лестница источников карты

| Ступень | `source` | Как | Что даёт | Когда нужна |
|---|---|---|---|---|
| 1 | `a11y` | API доступности ОС: AT-SPI2 / UI Automation / AXUIElement | роли, имена, состояния, действия; без вмешательства в процесс | большинство приложений: GTK, системный Qt, WinForms/WPF/WinUI, Cocoa, браузеры |
| 2 | `probe` | **Зонд внутри процесса**: библиотека, внедрённая при запуске, читает собственное дерево объектов тулкита и действует изнутри | полное дерево тулкита (классы, свойства, видимость, `enabled`) + модель `QAccessible`, даже если мост в ОС не собран; действия без ввода ОС и без порталов | приложения со своим тулкитом без моста доступности (kesl-gui), «бедное» дерево a11y |
| 2' | `cdp` | Chrome DevTools Protocol (`--remote-debugging-port`) | DOM и дерево доступности Chromium, клики и ввод через CDP | Electron и Chromium-приложения |
| 3 | `vision` | Снимок окна + OCR + простое выделение элементов; снимок отдаётся и ИИ | текстовые блоки и кликабельные зоны с координатами, `confidence` | всё, что не дало дерева: игры, canvas, удалённые рабочие столы, экзотические тулкиты |

Порядок выбора — сверху вниз. Ступени смешиваются: если дерево a11y
«бедное» (мало узлов, нет имён), `doctor` предлагает зонд или визуальный
слой, а `tree --source vision` строит карту по пикселям даже поверх a11y.

### Доказательство ступени 2 (2026-10-29, `docs/research/qt-probe-poc.md`)

kesl-gui 12.5 (свой Qt 5.9.5, QML, без моста AT-SPI) с зондом
`probes/qt5/` (`LD_PRELOAD`, хук `qtHookData[Startup]`, Unix-сокет, JSON):

- карта: окно, все кнопки («Scan», «Update», «Reports», «Settings», …) с
  текстами, классами QML, координатами, `enabled`; невидимые окна-диалоги;
- нажатие «View» синтетическим событием внутри процесса → приложение
  перешло на страницу «Protection Center», новая карта это показала;
- на Wayland-сеансе, **без портала и без диалога согласия**;
- выключенная кнопка («Reports», `enabled:false`) видна как выключенная.

## Лестница действий

1. **Семантика** источника узла: AT-SPI `DoAction` / UIA паттерны / `AXPress`;
   у зонда — `QAccessible` press или метод/сигнал объекта (`clicked`).
2. **Событие внутри процесса** (только зонд): `QMouseEvent`/`QKeyEvent`,
   отправленные окну тулкита. Не зависит от Wayland, UIPI, фокуса окна.
3. **Ввод ОС по координатам** (`via: input`): SendInput / CGEvent / XTest;
   на Wayland — портал RemoteDesktop с `restore_token` (согласие один раз).

Перед действием узел перечитывается; выключенный или исчезнувший →
ошибка (`disabled`, `stale`), а не «ok». После действия — проверка
результата там, где она возможна.

## Захват пикселей (для ступени 3)

| Среда | Способ | Согласие |
|---|---|---|
| X11 и XWayland-окна (на Wayland тоже) | `XGetImage` окна | не нужно (проверено в 00: окно kesl-gui) |
| Wayland-окна | портал ScreenCast в **одной сессии** с RemoteDesktop — координаты кадра и указателя совпадают (lumepeer ADR 0010) | один раз, дальше `restore_token` |
| Windows | Windows.Graphics.Capture / `PrintWindow` | нет |
| macOS | ScreenCaptureKit | разрешение Screen Recording |

## Зонды (ступень 2) — как устроены

- **Код зонда — на языке тулкита** (C++ для Qt), минимальный: обход дерева,
  свойства, действия, сокет. Вся логика (селекторы, нормализация ролей,
  рендер, MCP) — в Rust, в `hangui-probe` клиенте.
- **Протокол** — JSON-строки по локальному сокету
  (`$XDG_RUNTIME_DIR/hangui/<toolkit>-<pid>.sock`, на Windows — named pipe):
  `tree`, `node`, `act`, `events`. Описан в contracts.md §9.
- **Версии.** Зонд собирается под **точную минорную версию** тулкита цели:
  заголовки Qt 5.15 против Qt 5.9 ломают inline-код (`QJsonObject` в 5.15
  переведён на CBOR — ответ приходил пустым). Сборка линкуется с
  библиотеками цели, чтобы отсутствующая функция ловилась при сборке.
  hangui определяет версию тулкита цели (`strings`/символы QtCore) и берёт
  подходящую сборку из набора (CI-матрица Qt 5.6–5.15, 6.2–6.x). Чтобы
  сузить матрицу, зонд избегает классов с изменившейся раскладкой (JSON
  пишется вручную в `QString`) — проверяется в пачке 05.
- **Внедрение:**
  - Linux: `hangui launch -- <cmd>` с `LD_PRELOAD` (проверено). Подключение
    к уже запущенному процессу (`attach`) требует ptrace — на Ubuntu
    `ptrace_scope=1` разрешает только родителю, поэтому основной путь — запуск.
  - Windows: запуск процесса приостановленным + загрузка DLL до старта
    (тот же процесс-пользователь); повышенный процесс — только из
    повышенного hangui.
  - macOS: `DYLD_INSERT_LIBRARIES` работает только для приложений без
    hardened runtime; для подписанных — ступени 1 и 3.
- **Границы:** зонд внедряется только в процессы того же пользователя,
  которые пользователь запускает через hangui. Никаких обходов защиты ОС,
  повышения прав или внедрения в чужие сеансы.

## Модули

```
crates/hangui-core      модель Node (+source, confidence), селекторы, рендер, трейт Provider, слияние источников
crates/hangui-linux     AT-SPI, ввод (XTest/портал), захват (XGetImage/ScreenCast)
crates/hangui-windows   UIA, SendInput, захват, внедрение DLL
crates/hangui-macos     AX, CGEvent, ScreenCaptureKit
crates/hangui-probe     клиент протокола зондов, выбор сборки, launch/attach
crates/hangui-cdp       провайдер Chromium/Electron через CDP
crates/hangui-vision    OCR (`ocrs`) и выделение элементов по пикселям
crates/hangui-mcp       MCP-сервер
apps/hangui             CLI + TUI
probes/qt5, probes/qt6  зонды (C++), собираются CI-матрицей
```

## Что остаётся неизвестным (проверяют пачки)

- Глобальные координаты окна XWayland на GNOME/Wayland совпадают с
  координатами портала? — пачка 06.
- Качество OCR `ocrs` на интерфейсах (мелкий шрифт, тёмные темы) — пачка 07.
- Можно ли одной сборкой зонда покрыть все Qt 5.x, избегая inline-кода — пачка 05.
- Зонд в приложениях с защитой целостности (Kaspersky сам не помешал, другие
  могут) — фиксировать в матрице, пачка 10.
